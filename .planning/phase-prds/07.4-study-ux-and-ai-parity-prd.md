# PRD: Phase 07.4 Mobile Study UX and AI Parity Closure

**Date:** 2026-04-13
**Source:** Live Android device testing after release packaging
**Reference system:** `D:\projects\word-desktop-tauri`

## Goal

Close the remaining mobile study UX and behavior mismatches that are still visible during real-device usage. The acceptance baseline is desktop behavior and product intent, not the current mobile implementation.

## Problems To Fix

### 1. Redundant example prompt content pushes the submit area downward

Current behavior:
- In example-based choice questions, the sentence appears twice:
  - once as the main prompt area
  - again in the expandable example block
- This adds unnecessary vertical height and makes the submit area harder to reach.

Required behavior:
- Remove the duplicated prompt content in the red-circled area from the study card.
- Keep only the useful example/translation presentation.
- The submit area should stay closer to the bottom without forcing extra scrolling.

Acceptance criteria:
- Example-based questions no longer render duplicated prompt text above the expandable example card.
- Submit controls are visibly higher and require less manual scrolling.

### 2. AI passage generation should compose a real contextual passage, not just list wrong-word examples

Current behavior:
- Mobile AI output is still too close to a wrong-word listing or stitched example display.

Required behavior:
- Use desktop implementation as the functional target.
- Wrong words must be integrated into a coherent contextual passage rather than simply dumped as examples.
- Output should preserve structured rendering and wrong-word highlighting while feeling like a real passage.

Acceptance criteria:
- AI passage semantics match desktop intent: contextual composition first, wrong-word highlighting second.
- Output is not a flat list of example sentences or glosses.

### 3. Exiting mid-session does not make Today progress truthful

Current behavior:
- The exit dialog says progress will be preserved.
- But after leaving, Today/Home still shows `0/5` instead of the in-progress state such as `3/5`.

Required behavior:
- In-progress study progress must be reflected on Today immediately after exiting and returning.
- This should hold for resumed sessions without requiring session completion.

Acceptance criteria:
- Leaving a partially completed session preserves and surfaces current progress on Today.
- The Today snapshot/progress display matches the preserved in-progress session state.

### 4. Root/affix mode reveals the answer directly instead of testing and explaining properly

Current behavior:
- Root/affix study currently shows answer-like explanation content too early.
- The highlighted red-circled answer text should not be shown directly.

Required behavior:
- Remove direct answer reveal from the root/affix prompt area.
- Explain the example words instead.
- Highlight the tested root/affix segment inside each example word so the user can distinguish it from other letters.

Acceptance criteria:
- Root/affix prompt no longer directly shows the answer.
- Example words include explanation-oriented content.
- The tested root/affix segment is visually highlighted inside each example word.

### 5. Correct-answer distribution in multiple choice is too biased toward B

Current behavior:
- Choosing B repeatedly yields far too many correct answers.

Required behavior:
- Correct option placement must be much more evenly distributed across A/B/C/D.
- The placement strategy should be deterministic enough for repeatability but not visibly biased.

Acceptance criteria:
- Correct option positions are materially more balanced across A/B/C/D.
- Simple repeated guessing like “always choose B” no longer performs abnormally well.

### 6. Chinese-input questions need better bottom-keyboard ergonomics

Current behavior:
- For Chinese-input questions, input and submit feel awkward on phone.

Required behavior:
- When entering a Chinese-meaning input question, keep the keyboard anchored at the bottom and make the user flow fast:
  - focus input immediately
  - user types directly
  - pressing Enter/return submits the answer when appropriate

Acceptance criteria:
- Chinese-input questions autofocus reliably.
- Keyboard interaction feels bottom-anchored and immediate.
- Pressing return can submit the answer without forcing a reach to the button in the common case.

## Scope

In scope:
- Study-card layout cleanup
- Root/affix study prompt and explanation behavior
- Today in-progress progress truthfulness
- Multiple-choice answer-position fairness
- Chinese-input keyboard/submit ergonomics
- AI passage generation semantics aligned to desktop

Out of scope:
- Broad redesign of the full study UI
- New sync/account features
- Re-architecting unrelated navigation or packaging flows
