### 2.2 Reports chart point alignment

Port the Flutter chart math exactly instead of adjusting by eye.

Required behavior:

- The rendered visual dot center must equal the computed line point.
- The hitbox may be larger, but its center must be aligned with the visual point.
- Selected-day detail must update when the point/hitbox is tapped.
- Mode compact charts must use Flutter compact dimensions and `modeSeries[mode]`.

Acceptance:

- `scripts/reports-golden.ts` includes a center-alignment assertion for each point.
- Manual DevTools check shows dots on the line, not above/below it.
- `npm.cmd run test:reports` passes.

### 2.3 Today per-mode and interrupted-session sync

Replace total-only/ad hoc progress synchronization with Flutter-equivalent home-state fields.

Required behavior:

- Total progress and every row progress must read from the same refreshed Today home state or snapshot fallback.
- Returning from study before completion must refresh the page and show partial per-mode progress when Flutter/backend exposes it.
- Completing a mode must update that mode row, not just the purple summary card.
- Exiting study must not discard progress already submitted to the backend/session facade.

Acceptance:

- A test starts a mode, submits one answer, exits, refreshes Today, and verifies only that mode row updates.
- A test completes a mode and verifies the relevant mode row reaches target while other rows remain unchanged.
- No direct per-answer mutation of Today completion remains in mini-program page code or mock SDK.

### 2.4 Visible pull-down refresh state

Native pull-down alone is not sufficient. Port the visible Flutter loading affordance.

Required behavior:

- During refresh, Today displays a visible refresh/loading state equivalent to Flutter's top progress/loading indicator.
- The state is driven by the same async refresh boundary as `usePullDownRefresh`.
- Refresh completion clears the indicator even on error.

Acceptance:

- A UI contract test verifies refresh state renders.
- Manual DevTools refresh shows a visible in-page loading animation/indicator.

### 2.5 Per-mode completion summaries

Compare and port Flutter's completion summary behavior for every mini-program mode.

Required behavior:

- Completion is driven by `SubmitAnswerResponse.isComplete` and `summary`, not by local question-count shortcuts.
- Each mode uses Flutter's summary subtitle/next-action semantics:
  - `newWord`
  - `review`
  - `mixed`
  - `wrongWordReinforcement`
  - `rootAffix`
- Restart/next-mode actions follow Flutter flow where applicable.

Acceptance:

- Tests complete each mode and snapshot the summary mode label, accuracy, correct/incorrect counts, next action, and Today refresh behavior.
- The implementation report includes function-level comparison for `_CompletionPage`, `_AccuracyPanel`, `_summarySubtitle`, and mini-program counterparts.
