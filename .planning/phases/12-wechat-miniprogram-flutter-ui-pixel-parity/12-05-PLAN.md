# 12-05 - Add UI contract verification and screenshot QA workflow

## Objective

Add guardrails so the mini program cannot regress to placeholder English layouts or the wrong navigation structure after Phase 12.

## Read First

- `.planning/phases/12-wechat-miniprogram-flutter-ui-pixel-parity/12-CONTEXT.md`
- `.planning/phases/12-wechat-miniprogram-flutter-ui-pixel-parity/12-UI-SPEC.md`
- `apps/wechat_miniprogram/package.json`
- Existing mini program test/check scripts

## Tasks

1. Add a UI contract check script for the mini program source and built output.
2. The script must assert:
   - Account is not a bottom tab.
   - Four tab entries exist for Today, Plan, Wrong, and Reports.
   - AI tab/page/summary/generation entry points are absent.
   - Primary page source contains required Chinese headings from the UI spec.
   - Old placeholder phrases are absent from visible primary surfaces.
   - Required shell/drawer components exist.
3. Add an npm script for the UI contract check.
4. Run and document the verification sequence:
   - `npm.cmd run typecheck`
   - `npm.cmd run build:weapp`
   - UI contract check script
5. Open the built `dist` in WeChat DevTools and capture comparison screenshots for:
   - Today top
   - Today lower
   - Plan
   - Wrong Words
   - Reports
   - Account drawer
6. Record any remaining visual deviations as explicit follow-up items rather than leaving them implicit.

## Success Criteria

- Automated checks fail if the UI returns to the old English placeholder pages.
- Automated checks fail if Account returns as a tab or any AI UI appears in the mini program v1 shell.
- WeChat DevTools screenshots can be compared directly against the six supplied references.
- Phase 12 can be accepted only after both automated checks and manual screenshot comparison pass.
