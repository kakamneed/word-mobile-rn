# Phase 07.4: Mobile study UX polish and desktop-parity closure - Research

**Date:** 2026-04-13
**Status:** Complete

## Goal

Translate the latest live-device study UX findings into a practical execution shape that preserves desktop parity as the behavioral reference.

## Key Findings

### 1. The duplicate example prompt is a pure presentation bug, not a domain-rule issue

Evidence:
- `apps/mobile/src/screens/study/question-card.tsx`

Implication:
- This should be fixed in the study-card rendering layer, not by changing question payload semantics.
- The quickest win is to remove the redundant top-level sentence rendering for example-based questions.

### 2. Today progress truthfulness depends on preserved active-session state being surfaced, not just stored

Evidence:
- `apps/mobile/src/screens/study/study-session-screen.tsx`
- `apps/mobile/src/screens/today/today-screen.tsx`
- `apps/mobile/android/app/src/main/java/com/wordmobile/WordCoreModule.java`

Implication:
- The progress-preservation issue is likely in how Today computes or reads in-progress state after exit.
- Fix must include the state source and the Today projection layer together.

### 3. Root/affix mode currently conflates explanation and answer reveal

Evidence:
- `apps/mobile/src/screens/study/question-card.tsx`
- `apps/mobile/android/app/src/main/java/com/wordmobile/WordCoreModule.java`
- Desktop root/affix handling in `../word-desktop-tauri/apps/desktop/src/features/study/study-session-page.tsx`

Implication:
- The prompt contract and rendering treatment both need revision.
- The best parity path is “example words + highlighted tested fragment + delayed answer”, not a literal answer reveal in the prompt card.

### 4. Choice-position fairness should be fixed in question generation, not UI

Evidence:
- `apps/mobile/android/app/src/main/java/com/wordmobile/WordCoreModule.java`
- `../word-desktop-tauri/apps/desktop/src-tauri/src/services/question_builder.rs`

Implication:
- If B is overrepresented, the bug lives in correct-option placement logic.
- The fix belongs in the generation layer so every consumer benefits.

### 5. AI semantic parity is now mostly an input/output quality problem

Evidence:
- `apps/mobile/src/screens/ai/ai-passage-screen.tsx`
- `apps/mobile/android/app/src/main/java/com/wordmobile/WordCoreModule.java`
- `../word-desktop-tauri/apps/desktop/src-tauri/src/services/wrong_word_input_service.rs`
- `../word-desktop-tauri/apps/desktop/src/features/wrong-words/ai-passage-reader.tsx`

Implication:
- Mobile already has structured AI output plumbing.
- The next improvement is to make the generated content more passage-like and less stitched.
- This phase does not need to solve full cloud-model parity if local semantics can better mirror desktop structure and intent.

### 6. Chinese-input ergonomics are mostly a screen-level interaction problem

Evidence:
- `apps/mobile/src/screens/study/question-card.tsx`
- `apps/mobile/src/screens/study/study-session-screen.tsx`

Implication:
- Autofocus, keyboard anchoring, and Enter-to-submit should be addressed together as one interaction polish task.

## Recommended Planning Shape

Split Phase 07.4 into four execution plans:

1. Study-card density cleanup and Chinese-input ergonomics
2. Today in-progress progress truthfulness
3. Root/affix behavior and multiple-choice fairness correction
4. AI passage semantic alignment to desktop contextual composition

## Risks To Plan Around

- If root/affix highlighting is implemented only visually without changing the explanation structure, answer leakage may remain.
- If progress truthfulness is fixed only in the dialog copy, the trust issue remains.
- If AI semantic alignment is interpreted as “just add more text,” the output may still fail the desktop parity goal.
