<domain>
## Phase Boundary

This urgent inserted phase closes the highest-friction remaining study UX and behavior gaps found after real-device release validation. It is not a broad redesign of the mobile app. It focuses on making the active study loop, Today truthfulness, root/affix presentation, multiple-choice fairness, and AI passage composition behave the way the desktop product intends.

</domain>

<decisions>
## Implementation Decisions

### Study-card density and usability
- The duplicate example prompt text above the expandable example block must be removed.
- The study card should prefer compact, non-redundant content so submit controls are easier to reach.

### AI passage semantics
- Mobile AI passage generation should target desktop semantics: coherent contextual passage first, highlighted wrong words second.
- AI output must not degrade into a list of example sentences or gloss-only snippets.

### In-progress Today truthfulness
- Preserved in-progress study state must be reflected on Today immediately after exiting a session.
- Dialog copy promising preserved progress must match actual Today/Home behavior.

### Root/affix behavior
- Root/affix mode must stop revealing the answer directly in the prompt area.
- Example words should be used to explain and illustrate the root/affix.
- The tested root/affix fragment should be visibly highlighted inside each example word.

### Multiple-choice fairness
- Correct option placement must be more evenly distributed across A/B/C/D.
- The implementation may remain deterministic, but it must not have a visible “B bias”.

### Chinese-input ergonomics
- Chinese-input questions should autofocus and keep typing flow immediate.
- Return/Enter should submit in the common case where the user has entered an answer.

### the agent's Discretion
- Exact visual treatment for root/affix highlighting
- Exact deterministic strategy for option-position balancing
- Exact keyboard/submit implementation details, as long as mobile ergonomics clearly improve

</decisions>
