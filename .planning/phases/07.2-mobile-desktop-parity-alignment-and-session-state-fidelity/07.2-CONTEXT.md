# Phase 07.2: Mobile desktop parity alignment and session state fidelity - Context

**Gathered:** 2026-04-10
**Status:** Ready for planning

<domain>
## Phase Boundary

This urgent inserted phase aligns the mobile implementation much more strictly with the desktop product's actual semantics and state behavior. It focuses on session-state fidelity, Today and plan truthfulness, mode-specific task/source alignment, and mobile information architecture adjustments needed to match the desktop product intent more closely. It is not a broad redesign of all mobile screens, but a parity-and-trust correction phase driven by live testing gaps.

</domain>

<decisions>
## Implementation Decisions

### Session state fidelity
- **D-01:** Mobile study progress must survive leaving the study screen and returning later instead of always restarting from the beginning.
- **D-02:** The user should be able to leave any study mode and return to continue the current in-progress session.
- **D-03:** The feedback state must stay tied to the current answered question rather than prematurely rendering the next question above a previous-question result panel.

### Today and plan truthfulness
- **D-04:** Today progress must reflect real session and snapshot state rather than placeholder or fabricated progress values.
- **D-05:** Mode target counts shown on mobile must match the active plan semantics instead of arbitrary stub values.
- **D-06:** When editing the plan, mobile must offer the same key choice as desktop: apply to today or only apply from tomorrow.

### Mode-specific source and quantity alignment
- **D-07:** Mixed test must not keep reusing only the same new-word study set when the desktop behavior expects broader mode-specific sourcing.
- **D-08:** Each study mode should use quantity and source-selection behavior that aligns with desktop intent rather than generic or reused placeholder logic.
- **D-09:** The phase should prioritize semantic parity over cosmetic parity when the two conflict.

### Mobile information architecture parity adjustments
- **D-10:** The current separation of vocabulary and plan must be reconsidered so wordbook management can live under or closer to the plan surface, while still preserving an independent wrong-word page.
- **D-11:** This phase should explicitly compare mobile behavior against desktop implementation rather than only patching isolated visible bugs.
- **D-12:** The phase needs a dedicated parity-audit wave in addition to direct bug-fix waves.

### the agent's Discretion
- Exact persistence mechanism used to keep in-progress session state across exits
- Exact UI wording and placement for "apply to today vs tomorrow"
- Exact structural merge between vocabulary and plan surfaces while preserving wrong-word independence

</decisions>
