# Phase 07.2: Mobile desktop parity alignment and session state fidelity - Research

**Date:** 2026-04-10
**Status:** Complete

## Goal

Determine how to restore desktop-level behavioral fidelity on mobile after live simulation exposed broader state and parity drift.

## Key Findings

### 1. The current mobile implementation still relies heavily on stub semantics

Evidence:
- `apps/mobile/src/lib/mobile-bridge.ts`
- `apps/mobile/android/app/src/main/java/com/wordmobile/WordCoreModule.java`

Implication:
- Many of the currently observed mismatches are not isolated UI bugs; they come from stubbed mode counts, source selection, and progression semantics.
- A parity phase must compare against desktop truth, not keep layering fixes onto placeholder data only.

### 2. Session persistence is fundamentally missing, not just buggy

Evidence:
- `apps/mobile/src/screens/study/study-session-screen.tsx`
- Device test result: leaving and re-entering resets study instead of resuming

Implication:
- A real "resume current session" mechanism is required.
- This likely needs both UI state and bridge/backend session ownership to align.

### 3. Today is currently displaying semantically plausible but still artificial progress

Evidence:
- `apps/mobile/src/lib/today-client.ts`
- `apps/mobile/android/app/src/main/java/com/wordmobile/WordCoreModule.java`
- Device test result: counts move, but are still not faithful to the real plan/session behavior

Implication:
- Today must be re-grounded in real snapshot/session semantics rather than synthetic placeholders.

### 4. The "apply to today or tomorrow" behavior is a product rule, not optional polish

Evidence:
- Desktop `plan-editor-page.tsx`
- User explicitly called out the missing apply-today/apply-tomorrow decision

Implication:
- Plan editing parity is not complete until this branch exists on mobile.

### 5. This phase needs a dedicated parity-audit wave

Evidence:
- User explicitly asked for "一个 wave 来完整对比桌面端的各方面差异"

Implication:
- The phase should not be only "fix known issues".
- One wave must explicitly audit current mobile behavior against desktop implementation and close remaining high-value gaps discovered by that audit.

## Recommended Planning Shape

Phase 07.2 should be split into three waves:

1. Session state fidelity and study sequencing repairs
2. Today/Plan/mode semantics parity repairs
3. Desktop parity audit and closure wave

## Planning Guidance

- Treat desktop as the semantic reference, not just a visual reference.
- Fix state truth before polishing visual output.
- Use the final audit wave to avoid endless ad hoc bug rounds.
