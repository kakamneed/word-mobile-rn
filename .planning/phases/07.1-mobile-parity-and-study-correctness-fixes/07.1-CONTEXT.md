# Phase 07.1: Mobile parity and study correctness fixes - Context

**Gathered:** 2026-04-10
**Status:** Ready for planning

<domain>
## Phase Boundary

This urgent inserted phase closes high-priority mobile parity and correctness gaps discovered during live phone testing. It focuses on restoring missing learning content and fixing a study-session correctness defect that breaks the mobile learning loop. It does not redesign the broader review center or release-hardening work beyond what is required to make the current mobile build trustworthy for continued testing.

</domain>

<decisions>
## Implementation Decisions

### Missing learning content parity
- **D-01:** Mobile must expose the medical-English wordbook as a first-class selectable study source rather than shipping without it.
- **D-02:** Mobile must expose the root/affix learning mode rather than omitting it from the current learning loop.
- **D-03:** These are not optional enhancements for later polish; they are parity gaps against already-established product capability and should be fixed in this urgent phase.

### Mobile language consistency
- **D-04:** Mobile user-facing copy should use Chinese rather than a mixed or English-first interface.
- **D-05:** This phase should prioritize visible product surfaces where users currently encounter English or placeholder copy.
- **D-06:** The goal is practical Chinese-language usability, not a perfect i18n system in this urgent pass.

### Study correctness defect
- **D-07:** The Chinese-meaning input question on mobile must stop incorrectly marking all answers as correct.
- **D-08:** The same bugfix must also restore correct progression so users can advance after answering instead of getting stuck.
- **D-09:** Study correctness takes priority over parity polish; the mobile learning loop is not acceptable until answer validation and next-question progression match backend truth.

### Scope and urgency
- **D-10:** This phase is specifically an urgent mobile-fix insertion discovered through device testing, not a broad feature expansion.
- **D-11:** The inserted phase should focus on the four concrete issues reported from the phone: missing medical wordbook, missing root/affix mode, non-Chinese UI copy, and broken Chinese-input answer correctness/progression.
- **D-12:** Broader refinements discovered during this work may be noted, but should not dilute the urgent-fix scope anchor.

### the agent's Discretion
- Exact mobile UI locations where Chinese copy should be normalized first
- Exact navigation or entry points for surfacing medical and root/affix capability on mobile
- Exact shape of the fix for the Chinese-input answer handling bug, as long as it aligns with shared backend truth

</decisions>
