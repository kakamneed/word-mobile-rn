# Feature: Exam Practice And Vocabulary Intelligence

> Slug: `exam-practice-vocab-intelligence`
> Status: `mobile_in_progress`
> Updated: `2026-08-17`

## Product Intent

Make bundled and user-imported exam exercises a first-class Today learning mode, and turn in-context vocabulary behavior into explainable graph relationships and learning priorities.

## UX Contract

- Today shows a compact `单词学习 / 模拟练习` selector beside the page heading.
- Word mode preserves the existing Today experience.
- Practice mode selects exam type, year, paper/set, and section before opening the whole article and its questions in a dedicated reader.
- English words in exercise content can be tapped for meanings and marked/unmarked as unknown without leaving the question.
- Reading uses one continuous mobile window with the passage above all questions. A draggable edge bubble switches between separately remembered passage and question bookmarks; it must not split the screen into two panes.
- Choice selection is provisional. Correctness and explanations remain hidden in the reader; after submission, a section report shows the full status overview and reveals one cleaned answer/explanation only when its question is selected.
- Doing mode uses yellow current-article word/range marks and optional notes without revealing Chinese meanings. Analysis mode immediately projects persisted local-dictionary meanings for yellow words/phrases and may append paragraph translations bundled in the selected paper; it never requests a live translation provider.
- A stationary long press selects exactly the rendered word under the pointer and exposes `标记` beside Copy/Share. The mark command opens the three-level familiarity palette; dragging selection handles may still expand the range for phrase lookup and annotation.
- Cloze sections render compact parenthesized blank numbers and compact option rows with labels before option text. Other objective sections reuse the corrected left-label option layout without cloze-only blank formatting.
- Translation keeps only its source passage visible by default, and writing keeps only its prompt visible by default. Each reference answer is revealed independently by an explicit button; neither subjective type is scored in the current version.
- Wrong Words and Reports reuse the page-level learning-content selector. Practice wrong words rank red/yellow annotation evidence, while practice reports select one exam family and chart per-paper objective accuracy overall and by supported question type.
- The AI workbench exposes paper import and analysis tools; normalized imports are reviewed before saving.
- Priority and causal-analysis results show evidence, confidence, and limitations.
- Cloze uses a dedicated AI review format: wrong questions first with the minimum solving sentence, inline meanings for non-purple marked words, all-option distinctions, the actual knowledge gap, and causal words; correctly answered questions with marked options receive a brief distinction; marked vocabulary is ranked last by the local derivational-family real-exam total while retaining each headword's strict count and rank for audit. Pure-purple prior-article words never receive an inline gloss in the quoted sentence, regardless of their three-level familiarity value.
- Translation sections initially show only the English source and writing sections hide the bundled reference essay. Each reference translation/essay has an explicit reveal control; neither subjective type exposes submit or scoring UI.
- Wrong Words and Reports expose matching practice modes: practice wrong words rank red/yellow exercise marks, while reports select an exam family and chart whole-paper plus objective-type accuracy.

## Shared Domain/Data Contract

- Normalized catalog: paper, section, question, choice, answer, explanation, optional ordered `paragraphTranslations`, provenance, and question capabilities.
- Question capabilities: `browsable`, `answerable`, `autoGradable`, `causalAnalyzable`.
- Attempt evidence: selected answer, correctness when known, timing, answer changes, token lookup, unknown marks, and stable source IDs.
- Vocabulary evidence preserves original form, normalized form, offsets, sentence/article/question context, and optional canonical dictionary entry.
- Multi-word selections are first-class vocabulary evidence. The complete generated exam lexicon remains a read-only bundled asset; words and phrases the user actually inspects are promoted into indexed SQLite `entries` plus `entry_meanings` so graph evidence keeps a canonical entry without bulk database inflation.
- The bundled exam-corpus dictionary is generated from all passage, instruction, stem, and choice text. ECDICT supplies exact words, word forms, and recognized 2-6 word phrases; bundled seed books are fallback sources. A direct phrase entry always wins. If an arbitrary selected range is not a fixed dictionary phrase, the app may show an explicitly labeled `未收录固定词组；逐词` explanation only when every component word has a meaning.
- Same-article relations project into the existing graph `coOccurrence` relation with typed `sameArticle` evidence.
- Priority evidence combines deterministic cross-paper recurrence with attempt, vocabulary, mastery, urgency, recency, and optional AI causal-confidence inputs.
- Practice reports group current auto-graded attempt state by exam family and paper. Supported type series are listening, cloze, reading, and new type; translation and writing are excluded.
- Practice report contract groups non-null `exercise_attempts.is_correct` by exam/paper/section and emits whole-paper totals plus `listening`, `cloze`, `reading`, and `newType` accuracy buckets.

## Flutter Mobile Route

- Owner screen/widget: `TodayShellScreen` owns mode selection; a dedicated exam catalog/practice route owns exercise selection and reading; `AiScreen` owns import and analysis tools; `WrongWordGraphScreen` consumes graph evidence.
- SDK/bridge calls: new catalog, attempt, vocabulary-event, import, relation, and priority methods built on Rust/app-core contracts.
- Loading/cache/reload behavior: word mode first paint remains independent of large exam assets; catalog loads lazily; attempt and mark writes are local-first; Today/graph/AI caches invalidate after relevant commits.
- Orientation/gesture constraints: portrait-first practice reader, compact segmented selector, tappable token spans that do not conflict with scrolling/text selection, and keyboard-safe import review.
- First implementation slice: supported standard-choice bundled paper from Today selection through persisted result and resume.
- Current status: planning complete; normalized assets and storage-only exercise vocabulary tables are partial prerequisites.

## Tauri Desktop Route

- Owner view/window: exam catalog workspace, split reader/question pane, and AI evidence inspector.
- Shared APIs to reuse: the same Rust catalog, attempt, vocabulary-event, graph relation, import, and priority contracts.
- Desktop-specific layout: dense filter table/tree, side-by-side passage and question, hover lookup plus click-to-mark, and an evidence side panel.
- Mobile assumptions to avoid: do not copy the compact Today segmented control, bottom composer constraints, or forced single-column reader.
- First parity slice: open the shared catalog, complete/resume one standard-choice attempt, and inspect persisted vocabulary evidence.
- Current status: not implemented; contract parity is required during mobile work.

## Sync And Storage

SQLite remains the offline source of truth for imported catalog entries, attempts, occurrences, marks, relations, and analysis metadata. Bundled content is immutable; user imports use distinct provenance and stable IDs. Raw source images stay local by default. Normalized user-owned attempts and marks may later enter the existing sync outbox after conflict and payload rules are specified.

## AI Or Provider Implications

Cross-paper occurrence counts are deterministic. AI may help parse imports and interpret structured wrong-answer evidence, but it must not invent official answers, occurrence counts, dictionary meanings, or paragraph translations. Reading translations are immutable paper data. Causal analysis returns candidates, confidence, evidence, limitations, provider/model metadata, and a recoverable failure state. Cloze vocabulary priority is overwritten after provider output from SQLite strict `exam_frequency` / `exam_rank` evidence plus the bundled `KaoYan_3.realExamFrequency.derivationalFamily` index, so model prose cannot alter measured counts or ordering.

## Mobile Lessons Learned

- A `TextSpan` recognizer is hit-tested against glyph bounds, not the user's perceived word area. Preserve the visual span, but assign its following horizontal separator to the same recognizer so one-letter words do not become precision targets.
- Native tokenization is data enrichment, not a prerequisite for basic text interaction. Build visible tap targets synchronously and upgrade them only when the native result is at least as complete; otherwise one transient bridge failure turns a paragraph into permanently inert text.
- Source-tree dictionary tests do not prove Android runtime availability. Flutter assets live under `flutter_assets/assets/...`, while Rust reads an extracted filesystem directory; every new Rust-consumed Flutter asset needs an explicit Android copy route and a packaging-boundary regression test.
- A marked-token recognizer must not replace the tap route when long-press behavior is added. Tap cancellation and hold-to-adjust are two outcomes of the same pointer sequence and need one arena participant; separate or mutually exclusive recognizers can make one branch unreachable.
- Do not bind a long-press recognizer to every unmarked token: it prevents the platform selection gesture from expanding across a phrase. Use tap for the initial word mark and reserve the three-level long-press palette for already marked words.
- A dictionary containing several senses is not itself per-occurrence semantic annotation. Translation-backed matching is authoritative only where a reviewed, index-aligned built-in paragraph translation exists; elsewhere the local grammar fallback is best-effort and must remain replaceable by future checked-in context-gloss assets.
- Do not load the full exam catalog on the critical Today word-mode path.
- Do not force exam passages and choices into the flashcard-oriented `StudyScreen`.
- An answer-bearing question is not necessarily auto-gradable by the standard-choice renderer; capability validation must consider the interaction shape.
- Token offset, sentence, question, article, and attempt identity must be captured when the interaction occurs; they cannot be reconstructed reliably during later AI analysis.
- Keep storage relation names (`same_article`, `same_paragraph`, `same_sentence`, `same_exercise_item`, `canonical_entry`) explicit when projecting them into graph-level `coOccurrence` evidence.
- When reusing exam-paper content as dictionary examples, keep the original provenance object beside the rendered source label; downstream practice and graph features need stable paper/question IDs, not only a human-readable string.
- Keep wordbook-to-exam-family filtering in the enrichment script and checker, not just in UI display, so downstream examples cannot silently cross from CET into Kaoyan or medical books.
- Treat stems/options as fallback examples for vocabulary seeding. They carry provenance, but original passage text is the preferred learning context when available.
- Rust tokenizer offsets are UTF-8 byte offsets, while Dart string slicing uses UTF-16 code units. Persist Rust offsets as evidence, but locate rendered token text sequentially in Dart instead of slicing Chinese-prefixed text with byte offsets.
- Same-article evidence requires one article identity across passage, stem, and choices. Use deterministic offset namespaces for subregions rather than assigning each UI fragment a different article ID.
- A computed evidence detail is not useful if the graph panel only renders relation counts; source details must be part of the visible selected-node UI.
- A mobile reading-position switch is a bookmark problem, not a layout split. Keep one scroll controller and two saved offsets; a two-pane implementation changes the requested reading model and reduces the usable phone viewport.
- Persist draft answer changes without correctness. Otherwise a resumable attempt leaks grading before the explicit article-level submit action.
- Treat section-level reporting as the grading disclosure boundary. Do not render answer correctness or source explanation HTML back into every question card after submit.
- A dictionary mark and its displayed meaning are separate states. Recover old empty mark notes from the current local dictionary during annotation-state hydration, and never make local meaning visibility depend on provider state.
- Put selection actions in the native selection toolbar. A button rendered after a long article is not an operable substitute for a context action beside the selection handles.
- Flutter exposes platform menu actions as typed items. Filter by `ContextMenuButtonType` instead of localized labels so Android/iOS language changes cannot reintroduce unwanted actions.
- Dictionary coverage needs both type and occurrence metrics. Rare names and corrupted compounds dominate uncovered types, while basic function words dominate occurrences; report both instead of claiming a misleading binary percentage.

## Known Pitfalls

- `2026-08-27` - The high-frequency synonym audit is deliberately an exact-Chinese-sense relation, not a general-language thesaurus. It can omit semantically related words whose supplied Chinese gloss differs, and a shared gloss can still require later editorial review for context. Do not broaden the table with embedding similarity or spelling/root heuristics without a separately auditable source and acceptance rule.

- `2026-08-18` sequential-budget pitfall: HTTP 200 health probes do not prove fallback availability when each earlier provider can consume nearly the entire UI wall clock. Keep per-provider budgets explicit and ensure the sum of sequential provider windows remains below the caller timeout. Saved mobile provider configuration can also override compiled defaults; it was not inspected in this run because wireless ADB disappeared before `run-as` access.

- `2026-08-17` - A configured provider is not proof that later fallbacks are reachable in code. The former exam-only Agnes branch returned immediately on both success and failure, so healthy relay accounts were never attempted after a quota error. Provider probes and route-order tests must be kept separate: one proves account reachability, the other proves the product actually reaches it.

- `2026-08-17` - JSON normalization at the top level is insufficient for persisted AI reports. A provider or legacy task may encode `questions`, `optionAnalysis`, `correctMarkedQuestions`, or `vocabularyPriority` as a string while the outer response remains valid JSON; presentation code must treat every repeated field as untrusted and fall back to an empty local collection.
- `2026-08-17` - Reusing a timestamp as the task ID makes every retry a distinct inbox row. Persist updates by task ID, but project the user-facing inbox by the stable exam/paper/section identity so transient provider failures do not create duplicate reports.

- `2026-08-15` - Rust `str::char_indices()` offsets are UTF-8 bytes; Dart `String.substring`, `TextSelection`, and rendered text positions are UTF-16 code units. Passing the former as the latter can stay hidden for ASCII text, then throw during an asynchronous Unicode example rebuild and appear as an opaque gray release `RenderErrorBox`. Offset-unit semantics are part of the bridge contract and must be tested with BMP and supplementary Unicode before adding another consumer.

- `2026-08-12` - Reading-review distractors often preserve several source words while changing semantic roles, scope, or causal direction. Marked-word overlap is not evidence of correctness: for this paper, `laboratory + routine` narrows journal publication to laboratory reports, `government-funded research` is the object being commercially restricted rather than the object criticized by the OECD report, and `facilitate + investment` reverses the claim that investment return depends on distribution and access.
- `2026-08-11` - Study examples must use a stable synthetic article identity such as `study-example:<entrySourceId>`. Reusing an exam paper article ID would falsely turn inherited practice evidence into a current-article mark; generating a per-render ID would prevent later Study and practice screens from sharing the mark.
- `2026-08-11` - Do not ask the provider to calculate or rank real-exam frequency. It may explain why a word matters, but the application must overwrite word, meaning, mark level, occurrence count, rank, and priority order from local vocabulary evidence before display or persistence.
- `2026-08-11` - A prompt instruction alone is not enough to protect pure-purple words, and purple must not be inferred from `mark_level=familiar`: color scope and familiarity strength are independent. The request/native evidence boundary carries explicit prior-only scope, and the native result boundary removes an immediate parenthetical gloss after every `markScope=prior` word before Flutter receives it.
- `2026-08-11` - A valid JSON object is not a complete cloze review. Every wrong question needs non-empty source context, option analysis, conclusion, and knowledge-gap fields; otherwise Flutter must keep the task retryable instead of showing a partial review as complete.

- `2026-08-11` - Do not equate rank eligibility with formal-wordbook membership. Corpus terms need a real rank even below the promotion threshold; only the study-list promotion is thresholded.
- `2026-08-11` - Normalized assets currently store writing reference answers in `section.passage` and many missing stems as `Question N`. Counting every populated field literally inflates answer vocabulary and `question`; frequency collection must distinguish actual exam English from storage placeholders and reference content.
- `2026-08-11` - Inflections merge into an existing lemma for strict headword counting. Derivations must not be silently folded into that strict count or rank; the deliberate display contract stores a separate, auditable family total built only from explicit `同根` links. For example, `observe=6`, `observation=3`, `observer=1`, `observable=1`, and `observational=1` remain individually inspectable while all five display the family total 12 in cloze review.
- `2026-08-11` - Adding seed entries requires rerunning question-prep, graph-relation, and real-exam-example maintenance. The full question-prep rebuild exceeded a 120-second command window before succeeding with a 600-second window in 244.9 seconds; a short tool timeout is not evidence of generator failure.

- `2026-08-06` - Adding SQLite columns alone is insufficient for installed databases: the seed importer normally skips a populated vocabulary. Any bundled frequency-data revision needs a versioned maintenance marker and an explicit backfill path.
- `2026-08-06` - Do not reuse `entries.frequency` for real-exam counts. That field already drives wordbook study order; exam occurrences and rank require separate columns.
- `2026-08-06` - Stopword filtering must run both before and after word-family resolution. A non-stopword surface form such as `beings` can resolve to the stopword headword `being`; accepting the canonical result without the second check would reintroduce stopwords into the ranking.

- `2026-08-06` - Do not key mark color by a canonical family and key definitions by the exact bridge normalization. Light inflection heuristics can produce a stripped silent-`e` stem, so rendering must preserve both the exact and family aliases. Also do not rely on a single `hideToolbar()` during a custom long press: Flutter's native selectable-text recognizer may create its menu later in the same gesture; a palette must explicitly suppress that menu and collapse the selection after the platform long-press window.

- `2026-08-03` - Do not apply the former 420-token Chat Completions budget to Agnes 2.5 Pro Alpha section reports. The official Responses API documentation says reasoning models may consume output budget before a final assistant message and recommends at least 1,024 `max_output_tokens` to avoid an incomplete response. A 420 cap was a latency workaround for the old Flash route, not a valid Pro Alpha configuration.

- `2026-08-02` - Do not treat HTTP 200 from Agnes 2.0 Flash as a usable exam-analysis result. For a complete five-question causal request, the model can exhaust the entire output budget in `reasoning_content` and return an empty `message.content` with `finish_reason=length`. The bridge must keep this as a provider failure, never convert it into an empty successful analysis. The mobile Rust client also uses a no-proxy direct connection, so a local proxy-only success does not prove the device route is available.

- `2026-08-02` - Do not restore concurrent per-question causal requests for one article. Each request duplicates the full passage, translations, and marked vocabulary, multiplying provider latency and timeout risk. A section response must return a result object for every submitted wrong question, including an empty candidate list when no marked word is causal.

- `2026-08-02` - A complete five-question reading section with 24 marks is not a valid success proxy for the current per-wrong-question mobile route. Repeating all article marks and full context for each wrong question caused three 60-second direct-provider timeouts before the output cap was added. With a 420-token cap, the provider answered the same aggregate context in about 12 seconds but returned `finish_reason=length`; a later 300-token response had an empty content field. Keep a structural, bounded report schema and do not persist incomplete/empty provider output as a completed task.

- `2026-08-02` - Do not assume a successful HTTP response proves the intended context reached the provider. The earlier PowerShell request used the wrong body encoding and Agnes rejected it as malformed JSON; send non-ASCII passage/translation payloads as explicit UTF-8 bytes. Provider output may also be wrapped in a JSON code fence and must remain subject to existing normalization before persistence.

- Do not present an upstream provider outage as missing question coverage, and do not synthesize causal candidates when every provider fails. HTTP 503/no-account and timeout failures are retryable external-service states; retain the failed task with concise guidance and allow retry from the section report.

- `2026-08-02` - Do not diagnose an untappable visible word as a dictionary miss. Interaction tokenization and mark persistence accept unmatched words; dictionary coverage controls meanings, not whether a span can be selected. If another word changes color, inspect the actual `RenderEditable` boxes and the persisted normalized word. Never inflate hit boxes vertically because adjacent lines can then steal the pointer.
- `2026-07-31` - A recognizer attached to whitespace in a `SelectableText.rich` tree is not sufficient proof that indentation can be tapped; Flutter may omit that whitespace from recognizer dispatch. Use rendered selection boxes for a narrow fallback and guard it by pointer duration, movement, and the mark-request serial so exact taps and long presses do not double-fire.
- `2026-07-31` - Cloze assets contain ordinary numbers that can equal a blank number, such as `10 years`, plus ordinals such as `20th`. A blanket one/two-digit replacement corrupts the passage; formatting must be constrained by section question IDs and ordinary-number context.
- `2026-07-31` - A section-level AI action must not silently accept partial per-question success, because one surviving finding looks like only one wrong question was analyzed. It also must not call `getVocabularyPriority` while opening results: that API intentionally scans the corpus and is unrelated to deciding which user-highlighted words caused the current section's errors.
- Do not expand a word target by applying highlight styling to its separator or by capturing line breaks. The separator may share the recognizer, but it must remain visually transparent, and paragraph/cloze structure must retain its own non-interactive spans.
- Do not render plain non-interactive text while waiting for a per-paragraph tokenizer call, and do not clear usable local tokens in the tokenizer error path. Article pages create several tokenization requests at once, so a transient failure must degrade dictionary offsets, not remove the user's ability to mark a word.
